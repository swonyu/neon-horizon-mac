# Repository critique and repair record — second review

Reviewed published revision `e0e71c3` across all 40 tracked files: setup, preset,
Dock, native controls, wallpaper sources and output, tests, documentation, assets
and license. Independent reviews covered installer/recovery, Dock/controls and
wallpaper/build behavior. The [implementation plan](plans/2026-09-12-round2-repairs.md)
records the accepted changes. The [first audit](AUDIT-2026-09-12.md) is historical;
its source revision and measurements are not a description of every later change.

## Critique

The architecture remains appropriate: small Python tools, native macOS settings,
optional Lua controls and one offline HTML artwork. Keep it. Replacing this with
an app framework or custom clipboard database would add maintenance without
solving a demonstrated problem.

The biggest weakness was recovery at the boundary between a check and its later
write. Most tests covered files or preferences that were already different when
an operation started. Several operations still trusted that earlier observation
after a slow backup, app lookup or service stop. The image pipeline similarly
protected failed grading, but could publish half a rebuild when a later source
or encoder failed. These are more consequential than further unverified visual
polish.

Onboarding clearly distinguishes presets, manually selected settings, optional
apps and their separate undo paths. The new current-review link prevents the
older critique's obsolete geometry discussion from being mistaken for the
current design. The Terminal instructions now distinguish saved-profile
verification from seeing a new window. Most visual choices remain manual by
design: importing whole preference files would replace the recipient's setup.

## Boundaries that remain

- Native preference writes and launchd/file operations do not offer a shared
  atomic compare-and-set transaction with other apps. Rechecking closes the
  reproduced windows, but cannot prevent every possible simultaneous edit.
- Staging prevents source/grade/encode failures from touching prior outputs.
  Publishing several outputs individually is not a cross-file crash transaction.
- Prepared-asset checks validate structure; full image decoding remains part of
  the optional image preparation path.
- The browser-policy block still prevents fresh wallpaper preview/reload through
  the available tools, including alternate routes. Source geometry and simulation
  are not a rendered visual certification. Frame time, power use and subjective
  rain/reflection appearance remain unmeasured in this pass.
- Actual two-second Space switching, live window placement and next-login behavior
  require observation in the receiving Mac's session. CI cannot grant or certify
  Accessibility permissions.
- M5 Pro and higher is the intended audience. Only the original M5 Max/macOS 27
  beta setup has recorded local UI evidence; a disposable CI runner is not an
  additional supported-hardware certification.
- The repository is private. The owner can distribute the checked ZIP to another
  person without publishing personal settings; changing GitHub visibility is a
  separate owner choice, not part of these code repairs.

The CI uses read-only repository permission and official actions pinned to
commits, following [GitHub workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).
Its Lua interpreter uses the [Homebrew Lua 5.4 formula](https://formulae.brew.sh/formula/lua%405.4),
matching the embedded Hammerspoon Lua family used by these checks.
